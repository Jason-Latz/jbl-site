### Why the cache feels broken

Home and Writings returned Vercel `HIT` or `STALE` responses. The model has an immutable, one-year HTTP cache policy. Next's client navigation also reused the document in the observed Writings round trip. The React route still unmounted the desk. On return, asset reads, GLB parsing, scene construction, GPU uploads, shader preparation and first frames must happen again. Camera orbit is held by the mounted scene and is reset when it remounts. A prefetch or longer cache header cannot preserve that renderer or its camera. Preserve the small view state explicitly and give it an immediate visual representation when someone returns. Browser back/forward cache applies to document-level history restoration, a different path from the observed client-side route transition. [Next.js 14 caching](https://nextjs.org/docs/14/app/building-your-application/caching) · [Browser back/forward cache](https://web.dev/articles/bfcache)

### Where the work comes from

- **Desk startup and steady state.** The main model is 3.13 MB on disk and about 1.59 MB over Brotli. It contains 142 meshes, 130 materials and 71 embedded WebP images. The 13 active-theme lightmaps transferred about 94 kB total in the cold run. Four procedural overlays and shader compilation happen on the client. An instrumented desktop sample of the resting candidate scene recorded about 380 WebGL draw calls and 1.38 million submitted vertices or indices per animation frame, counting repeated work across passes. The scene switches to continuous rendering after reveal, even at rest. A smaller poster or more compressed lightmaps alone can only address a fraction of that work. [Scene startup and canvas](../components/desk/BakedDeskScene.tsx)
- **Activity and overlays.** Cold production home initiated Spotify Live from two surfaces alongside Duolingo, chess, album art metadata and guestbook reads. The candidate isolates the desk but still starts its polls and data hooks as soon as the interactive tree mounts. In a separate idle-and-return check, the candidate requested 13 Spotify images from its still-closed dropdowns. Mount artwork only after the corresponding dropdown opens, request thumbnail sizes, and reuse the last known summary on return. Keep the real playback semantics and let the poster and available links paint before signing up for live work. The GLB loader's error callback logs failures, while the candidate retry link depends on the React error boundary. Route network or decode failures through the same recovery state. [Spotify disclosure](../components/SpotifyNowPlaying.tsx) · [Desk orchestration](../components/desk/DeskInteractive.tsx) · [Loading and recovery shell](../components/desk/DeskHero.tsx)
- **Photography.** The layout assumes an initial width and fallback aspect ratio. It then measures the container and repacks rows as images decode, which can start a different width URL for photos already in flight. Tiles request twice the CSS width on every device, and progressive loading has a 1,200 px lookahead. Persist image dimensions at upload and backfill existing photos so rows can start with actual ratios. Use a small set of responsive, cacheable sizes and reserve the first requests for visible tiles. Preserve the gapless layout, captured aspect ratio, zoom reflow, metadata and original-quality lightbox. [Mosaic layout and loading](../components/PhotoMosaic.tsx) · [Transform rules](../lib/travel-image.ts)
- **Writing and delivery.** Archive HTML showed five articles. Both the live response sampled for an individual article and the candidate build identify the slug route as dynamic, and the live response sent `private, no-cache, no-store`. The current admin routes already call `revalidatePath` on writes. Prerender the known published slugs, serve cached HTML for new slugs, keep on-demand invalidation, and distinguish dependency errors from an empty archive or a missing article. Verify published content on a cold build and check publish, edit and unpublish together. The favicon and sitemap also returned 404. Published URLs visibly include generated `draft-` slugs. Improve new slugs and retain redirects if existing URLs change. [Published post queries](../lib/posts.ts) · [Article route](../app/writings/%5Bslug%5D/page.tsx)
- **Travel.** The globe is a distinct route and can remain one. Make a real place index available from first paint and let visitors reach the photos by keyboard before the canvas is ready. Test lighter marker batching and pause idle animation offscreen. Use the same cached photo dimensions and variants as Photography. Retain manual and estimated placement distinctions. ## Recommended direction

**The desk should establish the site's visual identity. Start with the visual you can control in Blender and give the visitor something to do immediately.** The live scene has the most recognizable imagery, especially the lamp, record player and books. The unpublished layout improves hierarchy and makes Writings fast to reach, but its small, dark overhead render loses some of the character of the full room. On the live site the pale editorial pages, dense tab bar and visible Admin link also compete with the identity set by the desk.

1. **Release the existing responsiveness work first.** Review the October changes on a branch based on current GitHub `main`, preserve the live compass preview, and validate a GitHub-triggered preview before merging. Confirm live `/` has zero desk requests and `/desk` serves successfully. Include closed Spotify dropdowns in the Writings → Home network check. Remove the remaining global gallery warmup once direct gallery delivery is in place.
2. **Create an art-directed first screen in Blender.** Render a three-quarter view from the desk's resting camera in warm light and lamp-off treatments, with a purposeful portrait crop. The poster and live reveal should use matching camera, exposure and composition. A/B this beside the existing overhead with a real phone at normal brightness. Keep the homepage minimal, with the artwork, writing link, and concise navigation. Keep the warm paper typography and copper accents. Consider moving Admin out of the public navigation and letting the activity ribbon sit below the principal artwork and writing link.
3. **Make the desk usable from its first frame.** Prototype the still with accessible, positioned HTML controls for the bookshelf, record player, notes, chess and work. Let them open the same panels or direct routes before loading the renderer. Add a deliberate control for freely looking around. Preserve the camera and focused object across visits, with stable deep links where appropriate. Confirm those interaction choices before building them. Keep the poster and controls when WebGL fails, is unavailable or is still preparing.
4. **Optimize the optional 3D scene with measurements.** Profile fetch, parse, overlay creation, texture upload, compilation, first drag and settled rendering separately. Merge compatible static geometry by material and lightmap, instance repeated pieces and export rigid overlay meshes offline where runtime generation is expensive. Retain motion where it matters, such as the needle drop and board moves. Change the render loop to redraw for camera, lighting and live activity, then settle when idle. Verify both themes, dragged camera, feature panels and GLB/lightmap fidelity with the production decoder. Keep Next.js and Supabase for this release sequence. Revisit a framework migration only if the static routes still miss their budgets after these changes.
5. **Fix photo delivery and make the budgets observable.** Record dimensions at ingest, choose variants once for the initial view, and verify network/visual quality before changing q92. Track real-user Web Vitals and the time from desk entry to controls ready. Add a repeatable production-preview smoke check for both themes, cold navigation, Back, and new publishing. Start with zero homepage WebGL requests, at most 350 kB through a settled home visit, zero photography asset requests on Writings or Experience, and at most 1 MB of initial Photography images on the standard phone profile. Target p75 LCP ≤ 2.5 s, INP ≤ 200 ms and CLS ≤ 0.1 on real traffic. Measure the optional 3D path separately so a quick poster cannot hide a slow reveal. [Web Vitals thresholds](https://web.dev/articles/vitals)
